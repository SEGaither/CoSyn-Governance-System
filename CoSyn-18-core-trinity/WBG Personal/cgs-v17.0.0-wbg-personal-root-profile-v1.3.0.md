# WBG Personal Root Profile — v1.3.0

## 1. Purpose

Define the private reusable User-specific writing layer between canonical WBG and project-specific writing governance.

WBG Personal owns only User-specific, project-agnostic writing specialization.

It does not own:

- universal CoSyn governance;
- generic WBG writing governance;
- project canon;
- project-specific creative decisions;
- project-specific workflow requirements;
- manuscript content.

## 2. Authority Hierarchy

Current authority sequence:

`Platform / host authority`
→ `CoSyn CGS v16.3.3`
→ `WBG Root Authority v1.1.0`
→ `registered WBG v1.0.0 base governance`
→ `registered WBG functional extensions through WBG v1.2.1 when triggered`
→ `WBG Personal v1.3.1`
→ `Project-Specific Writing Governance`
→ `Manuscript / Project Artifacts`

Current explicit User instruction outranks lower writing preferences within the authority allowed by higher-priority governance.

## 3. Composition Rule

WBG Personal is an overlay.

It must not:

- modify canonical WBG bytes;
- restate a Tier 2 rule as a competing authority owner;
- import one project's canon into another project;
- convert an ATTAS-specific rule into a universal personal rule without a reusable User-level basis;
- silently promote a project rule into WBG Personal.

Where Tier 2 already owns a User-level preference, WBG Personal references that authority and defines only its writing-specific application.

## 4. Personalization Boundary

A rule belongs in WBG Personal only when it is:

- specific to the User;
- applicable across materially different writing projects;
- writing-relevant;
- not already fully owned by higher authority;
- not dependent on one project's canon, characters, plot, POV, ending, or artifact identity.

If any of those conditions fails, the rule remains outside WBG Personal.

## 5. Project Rule Promotion

A Tier 3/project-specific rule does not become a WBG Personal rule through repetition or successful use.

Promotion requires explicit User authority to make the rule reusable at the personal writing-governance layer.

Until then:

`project rule = project only`

## 6. Fail-Closed Conflict Rule

If WBG Personal conflicts with:

- current explicit User instruction;
- canonical WBG;
- ratified CGS;
- an authoritative Tier 2 source;
- a narrower ratified project rule;

surface the conflict and follow the higher or narrower applicable authority.

Do not silently reconcile by rewriting either source.

## 8. Governed Learning Loop

WBG Personal is a reusable User baseline that may improve from actual writing-project evidence without absorbing project canon.

The lifecycle is:

`Generic WBG → Project-Specific WBG → reusable-pattern evaluation → User approval → WBG Personal revision → next project`

Project evidence may create a personal-rule candidate.

Project evidence does not itself create personal authority.

A candidate becomes active WBG Personal only through the promotion protocol in `WBG-Personal-Refinement-and-Promotion-Protocol-v1.3.0.md`.

## 9. Tier 2 / Tier 3 Evidence Boundary

Tier 2 is direct evidence of durable User-level governance within its actual scope.

Tier 3 is evidence of how those controls behave in a specific writing project.

Tier 3 may:

- confirm a reusable Tier 2 writing rule;
- reveal a candidate reusable pattern;
- expose a defect in the current personal baseline.

Tier 3 may not silently export project identity, canon, POV, plot, character rules, manuscript state, or project-only workflow into WBG Personal.


## 10. Canonical WBG v1.2.1 Hierarchy Synchronization

WBG Personal v1.3.1 is synchronized to canonical WBG v1.2.1, including the ratified project-package creation workflow extension.

Canonical WBG retains ownership of:

- WBG Root Authority and hierarchy;
- registered WBG v1.0.0 base governance;
- extension registration/synchronization;
- Anti-Plagiarism Check and Gate;
- Copyright Page Creator;
- AI Use Disclosure Creator;
- Writing Team Personas;
- generic writing operation state, diagnostics, project Q&A, User Artistic Authority, and manuscript versioning.

WBG Personal does not duplicate those artifacts or capabilities.

When a registered WBG extension activates, WBG Personal may add only a User-specific writing specialization that is independently supported and explicitly authorized. No such new extension-specific Personal rule is created by this revision.
