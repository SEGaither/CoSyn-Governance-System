# WBG Personal Refinement and Promotion Protocol — v1.3.0

## 1. Purpose

Define how existing Tier 2 and Tier 3 evidence may refine WBG Personal without contaminating it with project-specific material.

## 2. Evidence Classes

### A. Tier 2 — direct User-level evidence

A Tier 2 rule is eligible for writing-specific specialization when it is:

- authoritative/current within its own scope;
- User-specific;
- materially relevant to writing;
- project-agnostic.

WBG Personal should reference Tier 2 ownership and add only the writing-specific application that is not already fully expressed there.

### B. Tier 3 — project evidence

A Tier 3 rule, correction, workflow, or failure may reveal a reusable pattern.

Tier 3 evidence is not personal authority by itself.

A project-derived pattern must be classified as one of:

- `PROJECT_ONLY`
- `PERSONAL_CANDIDATE`
- `CONFIRMS_EXISTING_PERSONAL_RULE`
- `CONTRADICTS_PERSONAL_RULE`
- `INSUFFICIENT_EVIDENCE`

### C. Cross-tier corroboration

When Tier 2 already establishes a User-level rule and Tier 3 independently demonstrates the same writing behavior, the Tier 3 evidence may justify strengthening or clarifying the WBG Personal application.

It still must not import project canon.

## 3. Promotion Eligibility

A proposed personal rule must satisfy all of these:

1. User-specific.
2. Writing-relevant.
3. Project-agnostic.
4. Not already fully owned by canonical WBG.
5. Not already fully owned by Tier 2 without need for writing specialization.
6. Not dependent on one title, character, plot, POV, ending, chronology, manuscript identity, project-specific factual claim, or one-off workflow.
7. Supported by identifiable evidence.
8. Compatible with higher authority.
9. Explicitly approved by the User for personal-WBG scope.

Failure of any criterion blocks promotion.

## 4. Evidence Strength

Evidence may support a candidate through either route:

### Route 1 — Tier 2 anchored

An authoritative Tier 2 rule plus a legitimate writing-specific application is sufficient to create a personal-rule candidate.

Tier 3 evidence may corroborate it but is not required.

### Route 2 — project-derived

A pattern appearing in one project is a candidate only.

Repetition across materially different projects strengthens the candidate but still does not self-promote.

The User may explicitly promote a one-project pattern when the User intentionally declares it reusable across writing projects.

## 5. Explicit Promotion Required

No automatic learning mutates WBG Personal.

Promotion requires an explicit User act approving the candidate for reusable personal scope.

On promotion:

1. record source evidence;
2. record excluded project-specific material;
3. identify the owning WBG Personal artifact;
4. increment the applicable WBG Personal version;
5. regenerate provenance, manifest, integrity, and validation;
6. ratify only through explicit User authority.

## 6. Contradiction Handling

If a new project conflicts with an existing personal default:

- do not rewrite the personal rule silently;
- determine whether the project is a valid narrower specialization or evidence that the personal rule is too broad;
- preserve the project rule within Tier 3 while unresolved;
- amend WBG Personal only after explicit User decision.

## 7. Learning Loop

The governed learning loop is:

`Generic WBG`
→ `User WBG`
→ `Project Q&A`
→ `Project-Specific WBG`
→ `project execution evidence`
→ `reusable-pattern evaluation`
→ `User promotion decision`
→ `next User WBG version`

The loop reduces repeated governance work while preserving authority boundaries.

## 8. No-Gain Stop

A WBG Personal refinement reaches no material gain only after:

1. all accessible designated evidence has been classified;
2. all eligible personal candidates have been incorporated or explicitly excluded;
3. a complete audit finds no new material rule, collision, leakage, or missing dependency;
4. a confirmation pass on the identical unchanged state also finds no material defect or additional eligible rule.

A single self-review is not sufficient to certify no gain.


## 9. Canonical WBG Extension Evidence

A new or revised canonical WBG extension does not automatically require a Personal counterpart.

Classify its Personal-layer disposition as exactly one of:

- `NO PERSONAL SPECIALIZATION REQUIRED`
- `EXISTING PERSONAL RULE ALREADY APPLIES`
- `PERSONAL CANDIDATE`
- `CONFLICT / REVALIDATION REQUIRED`

Create a new Personal artifact only when a distinct reusable User-specific writing rule is justified. Generic WBG capability presence alone is insufficient.
